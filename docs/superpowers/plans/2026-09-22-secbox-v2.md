# Secbox V2 Implementation Plan

> **Unimplemented proposal.** This historical catalogue proposal is not the current runtime contract. Follow the README and V1 specification for shipped behavior. The current default grants no capabilities; raw networking and VPN require explicit root profiles.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a least-privilege, professional Secbox image that works from Linux and Windows hosts and includes the complete V2 tool catalogue on amd64 and arm64.

**Architecture:** Keep Docker Compose as the cross-platform interface and GNU Make as an optional wrapper. Split installation across Go, Python and immutable-source builder stages, copy only required artifacts into the Debian runtime, and make one executable smoke check the authoritative runtime contract.

**Tech Stack:** Docker/BuildKit, Docker Compose v2, Debian Bookworm, Go, Python/pipx, POSIX shell, GitHub Actions, Trivy, ShellCheck.

**Spec:** `specs/002-secbox-v2-cross-platform.md`

## Global Constraints

- Support Linux hosts with Docker Engine and Windows 10/11 hosts with Docker Desktop Linux containers.
- Support `linux/amd64` and `linux/arm64`.
- GNU Make is optional; Docker Compose is the canonical interface.
- Keep UID/GID 1000, read-only root, `no-new-privileges`, bounded resources, `cap_drop: ALL`, and default-only `NET_RAW`.
- Permit `NET_ADMIN` and `/dev/net/tun` only in the VPN override.
- Never execute an unpinned remote installer script.
- Pin immutable revisions or release versions for every non-Debian tool.
- Bundle SecLists read-only at `/opt/seclists` and link `/usr/share/seclists` to it.
- Do not add Docker socket access, host networking, privileged mode or GUI tools.

## Review Focus

- An unavailable or checksum-invalid upstream asset must fail the build, never produce a partial image.
- An arm64 build must not receive an amd64 binary.
- A missing executable or SecLists dataset must make the smoke check fail with an itemised name.
- A Windows absolute VPN path containing a drive letter or spaces must remain representable through Compose.
- A tool requiring a writable cache must work with only ephemeral home and `/tmp`.

### Task 1: Executable catalogue contract

**Files:**
- Create: `tests/tool-catalogue.sh`
- Modify: `toolbox/tools-check.sh`
- Create: `toolbox/tool-versions.txt`

**Interfaces:**
- Consumes: built image tag from `SECBOX_IMAGE`, defaulting to `secbox:local`.
- Produces: `secbox-check`, returning 0 only when every executable, dataset and manifest requirement is satisfied.

- [ ] **Step 1: Write the failing catalogue test**

```sh
#!/bin/sh
set -eu

image="${SECBOX_IMAGE:-secbox:local}"

docker run --rm --read-only --cap-drop ALL \
  --tmpfs /tmp:rw,noexec,nosuid,nodev \
  --tmpfs /home/secbox:rw,nosuid,nodev,uid=1000,gid=1000,mode=0700 \
  "$image" secbox-check

docker run --rm --read-only --cap-drop ALL "$image" sh -eu -c '
  test -f /opt/secbox/tool-versions.txt
  test -d /opt/seclists/Discovery/Web-Content
  test -L /usr/share/seclists
  test "$(readlink /usr/share/seclists)" = /opt/seclists
'
```

### Task 3: Cross-platform Compose interface

**Files:**
- Create: `scripts/secbox.sh`

- Modify: `Makefile`
- Modify: `docker-compose.yml`
- Modify: `docker-compose.vpn.yml`
- Create: `tests/compose-policy.sh`

**Interfaces:**
- Consumes: action `setup|build|check|shell|vpn|config|clean` and optional absolute VPN file path.
- Produces: equivalent Docker Compose behavior from POSIX shells and PowerShell.

- [ ] **Step 1: Write the failing Compose policy test**

The test renders base and merged configurations to temporary files and parses them with `docker compose config --format json` plus `jq`. It must fail unless:

- base user is `1000:1000`;
- base root is read-only;
- base drops `ALL` and adds only `NET_RAW`;
- base is neither privileged nor host-networked;
- base has no Docker socket or TUN device;
- VPN merge adds `NET_ADMIN` and only `/dev/net/tun`;
- all four project mounts retain their intended access modes.

Run `tests/compose-policy.sh`; expected RED until the test fixtures and canonical command interface are complete.

- [ ] **Step 2: Add POSIX launcher**

Implement strict action dispatch with `set -eu`, directory creation and an absolute-path check for VPN profiles. Use argument arrays or quoted positional parameters; never evaluate user input.

- [ ] **Step 3: Add PowerShell launcher**

Implement the same actions with `$ErrorActionPreference = "Stop"`, `New-Item -ItemType Directory -Force`, `Resolve-Path`, and direct `docker compose` argument invocation. Preserve paths containing spaces.

- [ ] **Step 4: Make GNU Make optional**

Keep existing targets but delegate to the POSIX launcher. The README's canonical flow must not depend on Make.
